# contracts：跨边界协议

状态：已预留职责目录，未建立可构建包或真实契约。

## 负责

- 有实际生产者与消费者的业务事件、Socket.IO 消息和 BullMQ 任务载荷。
- 同步操作的公共信封，例如操作 ID、资源 ID、内容/协议版本；业务冲突规则仍归所属服务。
- 必要的运行时消息校验，以及后期 gRPC 的 `.proto` 契约。
- 记录契约版本与兼容策略，避免删除字段导致旧 App 或排队任务无法处理。

候选结构：按需建立 `src/events/`、`src/realtime/`、`src/jobs/`、`src/sync/`、`proto/`。只在真实契约出现时添加文件；不维护一套无人使用的通用消息系统。

## 边界与验收

- 不导出 Prisma/Mongoose 模型、Nest Service、数据库凭据、密码字段或全部内部 DTO。
- GraphQL/OpenAPI schema 由提供接口的应用维护；生成客户端归 api-client，避免手写两份相互漂移的同名契约。
- 契约可以包含资源引用，不能赋予访问权限。actor、workspace 和对象归属在服务端复核。
- 首次启用时应验证生产者与消费者均可独立构建；关键消息非法输入被拒绝；增加字段时旧消费者的行为明确。

`tests/contracts/` 放系统级兼容验证，本包放协议定义，两者用途不同。
