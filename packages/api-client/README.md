# api-client：客户端契约与调用适配

状态：已预留职责目录，未生成客户端或建立可构建包。当前只有一个客户端时，简单请求先放 Web 对应 feature，不强制提前抽包。

## 负责

- 从已有 OpenAPI/GraphQL schema 生成客户端需要的类型和操作。
- 出现实际跨客户端复用时，提供明确的网络适配与统一错误映射。
- 根据已选客户端区分浏览器、服务端和未来原生入口，允许注入传输与身份上下文。

候选结构：`src/generated/`、`src/transport/`、`src/errors/`。生成流程、输入 schema 版本和更新方法与代码一起维护；不手工修改生成结果。

## 边界与验收

- 不依赖 Nest、Prisma 或服务内部源码；不在共享单例保存用户 Token/Cookie。
- SSR 的身份按请求传递，不把服务端密钥或内部地址打进浏览器包。
- React Query Hook、Zustand store 和页面交互留在各客户端。tRPC 若作为专项出现，不为它再维护同一接口的手写客户端。
- 浏览器 Axios、Next 服务端 fetch、未来平台请求 API 可以通过不同适配器工作，不承诺所有平台使用同一网络库。
- 首次启用验证生成可复现、错误类型明确、越权响应正确处理以及旧客户端兼容规则。
