# 面试工坊：技术学习与验收矩阵

> 当前五个应用已安装并通过脚手架级检查。本文仍是业务待实施规划，默认模板测试通过不代表功能、服务可靠性或性能目标已经实现。
> 产品主线：个人面试训练 → 多人模拟面试 → 3D 系统设计实验 → 工程复盘。
> 技术学习通过具体业务任务验收；覆盖常用能力，不追求用完框架全部 API。
> 产品范围与阶段命名以同目录 product-blueprint.md 为准；本文补充学习与验收证据。
> 从骨架开始的操作见 [bootstrap-guide.md](./bootstrap-guide.md)，已确认的多端、协议与阶段边界见 [基础边界决策](./decisions/0001-foundation-boundaries.md)。

Web/H5 共用当前 Web 应用；App、小程序和桌面端后续增加，从 A 开始约束统一身份、独立设备会话、内容版本与同步契约。
App 的 React Native、Capacitor、Flutter 路线，小程序框架以及 Electron/Tauri 暂未选型，不同时开发多个客户端。
统一接口、纯 TS 模型和平台中立设计令牌；DOM、原生视图、小程序组件和平台存储不承诺直接复用。

## 2. 架构演进与数据边界

初期采用 Next.js 前端与 NestJS 模块化应用，先把业务、权限和数据访问边界划清。
当前先创建五个目标应用和共享包的职责 README，不提前生成空的业务实现；第一阶段仅初始化 web 和 core-api。有可用闭环后，再通过拆分练习跨服务通信与运维。
最终目标结构如下，服务名称表示规划中的职责，不表示当前已部署。

| 部署单元 | 职责 | 自有数据 |
| --- | --- | --- |
| Next.js | 公开内容、个人后台、实时房间和 3D 交互入口 | 不直接读写业务数据库 |
| core-api | 统一身份、独立设备会话、权限、题目、回答、计划、小组、预约、房间成员 | PostgreSQL，使用 Prisma |
| studio-service | 房间消息、操作同步、3D 方案、文档版本、实验配置 | MongoDB，使用 Mongoose 或官方驱动 |
| report-worker | 消费任务、生成报告、内部状态 API、产物引用与消费去重 | 独立 PostgreSQL report 数据库或模式、专用数据库角色与对象存储 |
| ai-service（第四个业务微服务，演进目标） | NestJS 承载接口、权限、配额与业务集成；Mastra 承载 Agent、工具、Memory 与 Workflow | 初期是 NestJS 模块，后续独立部署；独立 PostgreSQL ai database/schema 保存会话、运行、草案与用量；Mastra 默认与 NestJS 同进程、同镜像 |
| Redis | 缓存、限流、在线状态、队列与跨实例消息支撑 | 不作为回答、权限或实验方案的唯一来源 |
| Nginx | HTTPS 接入、反向代理、请求体限制、WebSocket 转发 | 版本化配置 |

report-worker 不直接修改 core-api 的业务表；模式隔离时也用数据库权限限制访问。
core-api 通过任务载荷或受控接口提供报告所需数据，避免 worker 任意查询核心库。
服务之间传递业务 ID 和有版本的消息，不共享 ORM 实体，不跨库建立隐含外键。
跨服务操作通过业务状态、重试和补偿协调，不假设 PostgreSQL 与 MongoDB 共享事务。
先实现可靠的单服务事务，再引入 outbox、消费者去重和失败任务处理。
对需可靠投递的消息保存 outbox；事务提交后发布，接受至少一次投递并实现幂等。
Redis Pub/Sub 可用于可丢失的在线广播；关键业务事件另用具备持久与重试机制的队列。
实时房间以服务器状态为准，客户端按房间 ID、序号或版本恢复；重要状态允许重新拉取。
实时通道选用 Socket.IO；不再并行实现同用途的 GraphQL subscription 或另一套 WebSocket 协议。
GraphQL 聚合查询、REST 命令、Socket.IO 实时通知与 BullMQ 后台任务分工清楚；内部先 HTTP，后期一条真实链路练习 gRPC，tRPC 作为可选 TypeScript 专项。
GraphQL、gRPC、tRPC 可共存，不是进化替代关系；同一业务规则不复制成三份。独立网关/BFF 仍待评估，当前 Nginx 路由、core-api 聚合。
studio-service 通过 core-api 检查房间权限；角色变化需要影响既有连接，不能直读核心库。
原有三个业务服务保留；AI 先在 NestJS 中划分模块，形成稳定契约后再拆出 ai-service。
AI 模块通过所属服务的授权接口访问题目、回答与计划，不直接查询其他服务的数据库。
学习先用 NestJS 加模型 SDK 编写小型手动 Agent 循环；正式功能采用 NestJS + Mastra，不长期维护两套编排实现。
Mastra 通过 NestJS 自定义 Provider 创建并注入，由 NestJS Service 调用；不额外启动 Mastra HTTP Server，不增加第五个业务微服务。
NestJS 负责入口鉴权、参数校验、运行配额、业务 API 与后台调度；Mastra 负责 Agent、工具编排、Memory 和 Workflow 步骤。
共享 Mastra 实例时，每次 run 独立传递 actor、授权范围、会话、runId、取消信号和预算；不把当前用户写入单例可变状态。
模型供应商和具体模型暂不锁定；OpenAI Agents SDK 不作为项目当前编排选型，业务工具契约不依赖单一供应商。
BullMQ 负责持久任务排队、并发、投递和调度；Mastra Workflow 负责流程步骤、暂停、恢复与步骤结果。
每类失败只指定一个负责重试的层；队列重投恢复同一 run，已完成步骤不盲目重跑，业务写操作仍以操作 ID 保证幂等。

浏览器 Web Worker 负责受控的计算任务；Service Worker 负责浏览器请求和离线生命周期。
后端 BullMQ worker 执行持久后台任务；AI Agent 在限制内选择工具和步骤，四者不能互相替代。
浏览器关闭后，不保证 Web Worker、Service Worker 或离线同步继续运行；重要后台工作交给服务端。

| 手动 Agent 循环（G0 学习练习） | 理解模型选择工具、执行结果回传与停止 | NestJS + 模型 SDK、工具 schema、执行循环、轮数与预算、取消、错误 | 不依赖 Agent 框架解释并运行小型只读工具循环；非法参数、工具失败、超时与到达上限均有明确结果 |
| Mastra（正式编排选型） | AI 学习教练、模拟追问、架构评审 | Agent、Tools、Memory、Workflow、流式、运行追踪；NestJS Provider 集成 | NestJS 与 Mastra 在同进程、同镜像运行；两个并发用户不串上下文；锁定版本并验证 Node、ESM 与模块配置兼容 |
| 学习教练 Agent 与 Workflow | 开放式追问选择工具；固定计划流程控制步骤 | 单 Agent、窄权限工具、工具参数校验、Memory 隔离、步骤状态、确认与恢复 | 计划写入前展示预览并确认；篡改对象 ID 被业务服务拒绝；注入文本不能扩大权限；重试不重复写入 |

Next.js 和依赖的具体 API、缓存默认行为，以实施时锁定版本的官方文档为准。
Axios 不另建缓存；React Query 管服务端数据，Zustand 管客户端交互状态。
公开页面的服务端请求不必机械复用浏览器 Axios 实例；优先服从渲染与缓存方案。
GraphQL 先承担组合读取；REST 负责认证、上传和业务命令，避免为同一功能维护两套契约。
MongoDB 是为了练习文档边界而选用；初期数据量本身不能证明必须使用两个数据库。
Agent 适用于步骤未预定的任务；有明确顺序、分支和确认节点的计划流程使用 Workflow，可在步骤中调用 Agent。
Memory 的用户、会话与检索范围来自服务端可信上下文；配置框架 Memory 不等于完成业务数据授权。

## 4. 业务流程与扩展

### 4.1 答题与复习

选择计划 → 打开题目 → 保存草稿 → 提交回答 → 事务更新复习任务 → 展示进度 → 到期复习。
验收包含断网、重复点击、非法输入、权限越界、数据库失败和提交成功但响应丢失。
草稿恢复与正式提交采用不同语义；重试复用幂等键，并验证请求内容是否一致。
统计先实时查询；确认瓶颈后再采用缓存或异步汇总，记录数据延迟。
云端草稿从 A 使用稳定 ID、baseVersion、operationId 和 format/schema 版本；两会话编辑同一旧版本应提示冲突，不能静默覆盖。设备会话单独撤销，内容编辑与正式提交分开。

### 4.2 多人模拟面试

预约 → 邀请成员 → 入房校验 → 服务端计时 → 共同切题和消息 → 重连恢复 → 提交评分 → 复盘。
角色包括面试官、候选人和获准的观察者，成员关系由 core-api 管理。
WebSocket 连接建立与每类消息都检查权限，不能只在首次连接时校验一次。
验收包含重复消息、乱序、刷新、离开房间、角色变更和未授权订阅。
持久消息由 studio-service 写入 MongoDB 并分配 roomSeq 后确认；在线状态保存在 Redis。
第一版画布采用编辑锁或版本冲突检测；Socket.IO 不自动解决多人编辑冲突。
多人聊天、单人多设备同步和共同编辑同一个对象分别验收；后续 CRDT 是编辑/同步模块的局部升级，包含内容导入和旧客户端迁移成本，不提前实现通用协同引擎。

### 4.3 设计实验与工程复盘

领取场景 → 编辑 3D 拓扑 → 保存版本 → 设置模型 → 运行故障实验 → 比较方案 → 写取舍说明。
选取一项可用机制应用到真实平台，运行可复现测试，将结果关联到实验档案。
3D 动画展示模型中的请求和故障传播，不直接代表服务器正在发生的真实流量。
模型必须显示假设、单位、容量参数和简化条件，避免把动画速度当作测量结果。
领域图与 Three.js 渲染对象分离，保存稳定 ID、连接、参数和 schemaVersion。
模拟引擎支持确定性回放，重计算可进入 Web Worker；2D 与 3D 共享同一领域图。

### 4.4 离线学习与浏览器计算

用户主动下载学习包 → IndexedDB 保存账号下的题目与草稿 → 断网继续练习 → 前台恢复网络后同步。
离线范围与协同是两条轴：第一版离线草稿不包含完整离线业务，也不包含多人离线自动合并。更完整离线按操作范围扩展，在线协同可单独试验。
配置 manifest、图标与 HTTPS，按浏览器能力提供安装引导；安装与离线能力分别验收，不承诺所有浏览器表现一致。
正式提交与离线草稿分离；待同步操作有本地 ID、幂等键、版本和状态，不把旧数据直接覆盖到服务器。
应用打开或回到前台时检查真实接口可达性并重试；联网提示只是线索，不证明服务可用。
Background Sync 仅作为浏览器支持时的增强，验收基线是前台重试，不能承诺关页后完成同步。
恢复同步后重新鉴权，处理会话过期、权限撤销、服务端版本变化和用户主动丢弃草稿。
Workbox 使用明确路由白名单；私人 API、认证、GraphQL、Socket 和 Next RSC/流式响应不进入通用运行时缓存。
离线包只存用户主动选择且允许离线保存的数据；退出清理账号缓存与 IndexedDB，处理浏览器共享设备场景。
更新提示与用户保存草稿协调，避免自动切换 Service Worker 时中断编辑；验证资源版本和旧缓存清理。
实验室计算移入 Web Worker，以任务 ID 标记版本；大数据使用 Transferable，并处理转移后的失效引用。
采用分批计算、协作取消或终止并重建 worker；单独发送取消消息不能中断正在执行的同步长任务。
分别记录主线程长任务、输入响应与计算耗时；worker 通信开销也纳入优化证据。
旧离线草稿随内容/协议升级应能比较、另存或迁移；禁止旧客户端整份覆盖新协同状态。离线存储是平台适配，Workbox/IndexedDB 不直接成为原生或小程序的通用实现。

### 4.5 AI 反馈与学习教练 Agent

选定回答与目标 → 明确授权材料范围 → 流式生成反馈与来源 → 检索补充材料 → 推荐练习 → 预览计划 → 用户确认写入。
G0 先用 NestJS + 模型 SDK 写一个小型手动 Agent 循环：接收任务、模型选工具、校验调用、回传结果、继续或停止。
G0 使用少量只读工具，覆盖错误、取消和轮数上限，用于理解原理；正式功能不继续扩建自制编排框架。
G1 使用 NestJS + Mastra：通过自定义 Provider 注入实例，由 Service 处理模型流式、取消、结构化结果校验与错误呈现。
先验证锁定依赖版本、Node 运行时与 ESM 配置；不假设 NestJS 默认模块配置可以直接兼容，具体调用 API 以锁定版本为准。
G2 先用 PostgreSQL 全文检索，按评测需要再添加 pgvector；检索、缓存和引用均保留用户与文档授权边界。
G3 用 Mastra 单 Agent 与少量工具完成开放式追问；有确定步骤的计划预览、确认与写入用 Workflow 编排。
工具包括读取目标、查询获准记录、检索资料、生成计划草案、提交已确认的计划；多种 Agent 模式仍属于同一 ai-service。
每个 run 分别建立 actor、授权范围、会话与 Memory 标识、预算和取消状态；并发验收不得出现历史、工具结果或身份串用。
工具的 actor 与权限来自服务端会话，不能信任模型生成的用户 ID；每次读取或写入都由所属服务重新校验。
业务权限由 Guard、工具执行器和业务服务落实，不依赖 Prompt、模型自律或单独的 Agent guardrail。
写操作先产生带版本的预览，用户确认后由服务端复核范围、参数和权限；重试复用操作 ID，防止重复建计划。
后台长任务由 BullMQ 调度，Workflow 保存步骤状态；明确模型瞬时错误、工具错误和进程崩溃分别由哪一层恢复，避免嵌套重试放大调用和费用。
队列重投使用原 runId 与业务操作 ID，恢复或查询已有 Workflow；确认过期、输入版本变化或不可恢复错误需要明确终止或重新确认。
检索文档和工具结果作为不可信材料；其中的指令不能改变系统规则、工具权限、预算或确认要求。
运行设最大步骤、输出量、时间、费用与工具调用限制；限制模型出口，避免任意 URL 抓取或执行任意代码。
流式事件有 runId、序号和状态；断线后查询运行结果，区分取消展示与服务端执行终止，避免重连自动重复计费。
固定评测集包含正常反馈、无依据答案、越权检索、提示注入、工具失败、取消与重复提交，并记录模型与提示版本。
分别评估引用正确性、建议可用性、权限有效性、工具执行成功率、延迟和成本；AI 评分是练习反馈，不作为客观能力认证。

## 5. 必须补齐的工程主题

| 主题 | 规划任务 | 可检查结果 |
| --- | --- | --- |
| 身份与权限 | 统一用户、经验证登录身份、独立设备会话、定向撤销、成员角色、对象归属、公开分享范围 | 修改资源 ID 和角色参数也无法越权；权限变化影响请求、已有连接与运行恢复；单设备退出不影响其他设备 |
| Web 安全 | 输入验证、输出处理、CSRF、CORS、限流、上传限制、密钥管理 | 按认证方案检查跨站请求；敏感配置不进浏览器；文件类型、大小、访问权限有约束 |
| 自动化测试 | 业务规则单测、数据库集成测试、登录与答题 E2E | 测到权限、重复提交、事务失败和重连；修复重要缺陷后加入防复发用例 |
| 可观测性 | 结构化日志、错误上报、trace ID、基础指标与追踪 | 从一次用户错误找到 API、数据库或任务；日志不记录完整私人回答与认证秘密 |
| 可靠任务 | 超时、退避、幂等、重试上限、失败队列、手工重放 | worker 中途退出后任务可恢复；重复执行不会生成重复有效产物 |
| 数据与发布 | 迁移、兼容消息版本、备份、恢复、滚动发布、应用回滚 | 在隔离环境恢复备份；旧版本应用与迁移兼容性有说明；记录恢复时间和数据损失窗口 |
| 性能 | 前端包体与交互、3D 帧率、API 延迟、SQL、缓存和队列积压 | 固定数据与环境，保留基线、测量方法和优化结果；同时检查正确性 |
| 无障碍与体验 | 键盘、焦点、屏幕阅读语义、加载空错状态、减少动画 | 核心流程可用键盘；3D 有可访问的列表或 2D 表示；动画可减少或暂停 |
| API 与协作 | 契约、统一错误、分页、请求 ID、PR、ADR、英文说明 | 新客户端能理解接口；每次主要决策记录问题、候选方案、选择与代价 |
| 多端兼容与同步 | 内容与协议版本、平台适配、冲突、旧离线草稿恢复、最低写入版本 | 同账号多设备不丢内容；旧 App 返回行为明确；错误记录客户端与应用版本；无用界面实现不提前复制 |
| 运维与成本 | 环境隔离、健康检查、资源配额、依赖升级、云权限 | 不把测试环境当生产；能解释基础费用、故障影响与最小权限 |
| 离线与本地隐私 | 账号隔离、显式下载、过期清理、前台同步、冲突与存储降级 | 两个账号不共享草稿；关页再打开可恢复待同步状态；不依赖 Background Sync 完成验收 |
| AI 安全与可靠性 | 每次 run 上下文隔离、提示注入、检索权限、工具授权、写入确认、预算与评测 | 并发用户不串上下文；权限独立于 Prompt；私人内容无法越权检索；失败不误报成功；运行记录脱敏且有保留期限 |
| AI 编排与调度边界 | NestJS Provider 生命周期、Mastra Workflow 状态、BullMQ 重投、幂等与恢复 | 第四服务同进程集成；每类失败只有明确层重试；进程重启后恢复同一运行；已完成写操作不重复执行 |

数据恢复、业务撤销、应用版本回滚和数据库迁移回退是不同操作，分别设计。
备份覆盖 PostgreSQL、MongoDB、对象文件及必要配置；验证备份可恢复比显示成功更重要。
恢复演练使用隔离环境；生产数据恢复需定义停写、对账、切换和审计程序。
定义并测量 RPO（可接受数据损失）和 RTO（恢复时间），不承诺未经演练的数值。
单机多容器、单个 Nginx 或多个进程均不能自动证明高可用。

## 6. 分阶段学习顺序

| 阶段 | 学习重点 | 可交付范围 | 进入下一阶段的证据 |
| --- | --- | --- | --- |
| 0. 基础和契约 | TypeScript、HTTP、SQL、React 状态、业务模型 | 十几道题的原型、数据关系图、API 草案 | 独立解释请求、类型与表约束；列出提交失败和越权情形 |
| A. 个人闭环 | Next.js、React、Tailwind、shadcn、NestJS、PG、Prisma、IndexedDB 基础、设备会话与版本协议 | 登录、题库、回答、复习、云端草稿及本地恢复；模块化核心；初步 Docker 部署与日志 | 自己连续使用；两会话旧版本修改可检测冲突，退出一台不影响另一台；刷新恢复草稿且不串账号；事务、权限和错误状态有测试；可重复部署；能独立改业务规则 |
| B. 多人闭环 | GraphQL、Axios、React Query、Socket.IO、Redis 在线状态、MongoDB 消息 | GraphQL 工作台、小组、独立 studio-service、文字面试房 | 两个浏览器与两副本协作；重连补拉、去重、角色限制可演示；服务可独立部署 |
| C. 实验室 | Three.js、Zustand、Web Worker、MongoDB 场景、版本与并发 | 拓扑编辑、保存恢复、可取消的计算、模型实验、回放与简化视图 | 完成一个架构实验；长计算不阻塞输入；旧结果不覆盖；撤销与编辑冲突明确；资源可释放；能解释模型限制 |
| D. 异步可靠性 | report-worker、Redis/BullMQ、事务 Outbox、幂等 | 独立报告服务、状态接口、报告导出和可靠投递 | 停消费者、重复任务和超时后，答案不丢且报告不重复；跨库权限与一致性可解释 |
| P. 离线扩展（个人闭环与同步接口稳定后） | PWA、Service Worker、Workbox、IndexedDB 同步 | 显式离线包、草稿与待同步操作、版本更新提示 | 离线编辑可恢复；前台同步能处理冲突；不同账号隔离；Next 私人响应未被通用缓存截获 |
| E. 工程维护 | CI/CD、Nginx 完整配置、跨服务追踪、指标、备份与恢复 | 完整运维演练、应用回退、隔离环境数据恢复 | 从错误定位根因；恢复数据可核对；旧镜像兼容回退；演练记录 RPO/RTO |
| F. 优化与展示 | 实测性能、系统设计、英文演示与技术取舍 | 测量报告、SQL/缓存/渲染优化、架构图、英文项目档案 | 测量可复现；临时需求可拆解与修改；能接受英文追问并解释取舍 |
| G0. Agent 原理 | NestJS + 模型 SDK、手动工具循环、运行上限 | 小型只读 Agent 学习练习与数据流记录 | 独立解释工具调用循环；参数非法、工具失败、取消与达到上限有明确结果；不扩建第二套正式编排框架 |
| G1. NestJS + Mastra 基础 | 自定义 Provider、模型流式、结构校验、run 上下文 | 同进程 AI 模块、回答反馈、运行状态、取消与预算 | 运行时与 ESM 兼容；两个并发用户不串上下文；输出可验证；密钥不外泄；断流与预算耗尽状态明确 |
| G2. 授权检索 | PG 全文检索、分块与来源、可选 pgvector | 带引用的回答与学习材料检索 | 固定评测可复现；无资料时不编出处；越权材料不会进入上下文 |
| G3. Agent 与 Workflow 可靠性 | Mastra Agent/Tools/Memory/Workflow、业务权限、确认、BullMQ 分工、幂等、评测与追踪 | 学习教练生成并确认计划；形成契约后拆出第四个 ai-service，NestJS 与 Mastra 同进程同镜像 | 注入和越权用例通过；Memory 隔离；崩溃后恢复同一运行；重试责任明确且不重复建计划；成本、延迟与成功率有记录 |

阶段顺序遵循产品蓝图；测试、安全、日志与部署从 A 开始，E 负责完整演练与补强。
P 与 G 是可独立实施的扩展分支；G0 → G1 → G2 → G3 从 A 的授权业务闭环起步，G3 的可靠执行复用 D 的模式，不要求先完成 P。
E/F 继续覆盖新增离线与 AI 能力的维护和性能验证；加入新能力后补做相应演练，不以功能出现等同于已学会。
英文说明贯穿各阶段；基础薄弱时补充阶段 0，不把部署与权限推迟到最后。
不以固定周数承诺完成时间；以可演示的验收证据决定进度。

## 7. 掌握证据与 AI 使用规则

每个主题保留四份证据：设计解释、可运行实现、异常验证、独立修改记录。
完成一个功能后，不看实现画出数据流，指出权限边界、事务边界和失败后的状态。
再抽取一个变更自行完成，例如“只有面试官可切题”或“提交十分钟内允许修改”。
故意制造一次可控故障，通过日志和指标定位，再说明影响、修复和防复发措施。
隔一段时间换业务重做同类问题，例如把提交幂等迁移到报告生成，检查迁移能力。
用英语录制简短演示，再请同伴临时追问；避免只背固定介绍。
AI 可用于生成草稿、比较方案和辅助排障；交付前必须解释、运行并验证关键行为。
开发时使用 AI 与产品内实现 Agent 分别验收；能使用工具，不代表已掌握模型调用、授权检索或 Agent 可靠性。
AI 功能保留评测数据、提示与工具版本、脱敏运行证据；记录失败案例，并能独立修复一条工具链路。
对比 G0 手动循环与 G3 Mastra 运行记录，解释框架接管了什么，权限、幂等、预算与业务正确性仍由哪些应用边界保证。
无法说明生成代码的权限、并发或失败行为时，该部分仍标记为未掌握。
算法、JS 执行机制与英语听说另设练习；产品功能不能替代所有基础学习。

## 8. 性能与成果声明的边界

生成十万条数据可以验证索引与查询方法，不能宣称拥有真实十万用户经验。
本地压测结果只适用于记录的硬件、数据、配置、并发模型和测试窗口。
3D 实验是教学模型；真实平台指标来自实际埋点、追踪、压测和数据库执行计划。
展示报告应包含结果、复现方式、限制与剩余风险，避免将规划描述成已实现能力。
离线能力与 AI 反馈/学习教练现已纳入扩展规划，尚未实现；NestJS + Mastra 为正式 AI 编排选型，供应商和具体模型待定。
App、小程序、桌面端、音视频与支付仍后续单独评估；多端账号与数据边界从 A 纳入，客户端目录按选型增加。阶段设计、框架选型和资料引用不代表集成已运行通过。
