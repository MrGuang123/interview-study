# ADR 0001：基础边界、多端与渐进实现

- 状态：基础方向已确定；本文件明确列出的客户端/部署选项仍待评估。
- 日期：2026-10-21。
- 背景：先建立整体结构与职责，再逐步填充；同一账号支持 Web、H5，以及后续 App、小程序、桌面端。语雀是多端连续使用的体验参照，产品仍是面试学习平台。

## 1. 仓库与服务

采用 pnpm workspace。Web 与四个目标业务服务独立组织；各 Nest 应用采用 CLI standard-mode，各自维护构建、配置和 `package.json`。根目录不是运行时总控服务，AppModule、DDD 聚合根和 API 网关是不同概念。

| 应用 | 所有权 |
| --- | --- |
| web | Web/H5 展示、交互、浏览器缓存与平台适配 |
| core-api | 用户、登录身份、设备会话、工作空间、题目、训练、提交、复习与预约 |
| studio-service | 房间、消息、场景与其内容版本；MongoDB 为计划学习选型 |
| report-worker | 确定性报告、导出、任务状态及结果；自有 PostgreSQL report 存储 |
| ai-service | 会话、AgentRun、工具记录、建议、用量和评测；自有 PostgreSQL ai 存储 |

目录可以先完整建立，服务不要求首日全部实现和部署。先做 Web + 模块化核心，再按业务和学习阶段提取。后台进程数量不等于业务服务数量；第二种数据库和服务拆分要记录带来的收益与成本。

每个服务只操作自己的数据。跨域读取/写入通过授权接口和有版本事件，不建立全局数据库客户端、跨服务 JOIN 或统领所有业务的全局聚合根。

## 2. 入口与通信

- Nginx 负责边缘代理、TLS 和流式/实时连接转发。
- 当前 GraphQL 聚合由 core-api 承担；独立 API gateway/BFF 仅在聚合、客户端适配或部署需求明确后评估，不作为第五个业务服务先行创建。
- REST 负责认证、上传及业务命令；GraphQL 负责组合读取。这是本项目分工，不是框架能力限制。
- Socket.IO 负责房间实时通道，消息补拉和同步恢复依赖持久数据；不同时为同一功能增加 GraphQL subscription。
- BullMQ 负责可重试的后台任务，关键副作用采用幂等与必要的 Outbox/消费去重。
- gRPC 是后期内部通信实践，先选一条真实链路，例如 AI 获取练习上下文。
- tRPC 是可选 TypeScript 专项；不复制主干接口实现，也不因名称相似认为它是 gRPC 或 GraphQL 的后继。

跨端客户端不依赖 Next 专属入口才能完成核心业务；Server Actions 可以做 Web 适配，但后端仍是业务权威。

## 3. 多端身份、界面与适配

统一内部用户 ID，登录身份和设备会话分开；各设备独立更新、过期与撤销会话。HTTP、实时连接、后台任务和恢复同步按当前权限校验对象归属。

接口契约、纯 TypeScript 模型、模拟算法和设计令牌可复用；DOM、shadcn 组件和浏览器后台能力不假设能原样迁到所有端。

| 平台 | 已确定 | 待评估 |
| --- | --- | --- |
| Web/H5 | Next.js、React、Tailwind、shadcn；共享 Web 代码 | 具体页面响应式与交互 |
| App | 复用账号、权限、数据与协议 | React Native 与 Capacitor 等路线；Flutter 未选定 |
| 小程序 | 统一后端，按平台适配网络、身份、存储和实时协议 | 是否采用 Taro、具体客户端能力范围 |
| 桌面 | 优先评估复用 Web 界面 | Electron/Tauri；加载线上内容或打包本地资源 |

设计令牌在平台中立源中维护，分别映射到 Web CSS/Tailwind、未来原生主题与小程序样式。客户端实现确定前不创建假定某框架的空应用。

桌面打包路线必须验证 Next SSR/Server Actions 等服务端能力与本地资源的边界。Three.js 场景有独立领域数据；移动端可以先只读/2D，不要求功能完全一致。

## 4. 同步的演进

离线范围与协同程度是两个维度：可以先做在线多人协同，也可以先扩大单人离线功能，没有固定的单线升级关系。

第一版采用在线同步、本地草稿、冲突提示；完整离线范围是后续明确的业务集合，不包含无网络时调用云端 AI 或完成服务端最终确认。

当前合理预留：稳定内容 ID、内容格式版本、必要的同步协议版本、操作去重、基础版本检查、账号隔离、附件独立引用和删除/重连恢复规则。草稿与正式提交分开；各服务为自己所属内容提供同步，不创建跨所有数据库的同步事务或另一份真相。

未来共享笔记/画布可评估 Yjs 等 CRDT，影响主要局限于内容编辑、同步与持久化。结构化 JSON 不等于协同历史；迁移需要初始化协同状态、处理旧客户端整份覆盖和未上传旧草稿，并保留比较/另存/恢复路径。不能用代码回退代替数据迁移恢复。

现在不实现全站 CRDT、万能同步引擎或所有业务的事件溯源。评分、提交、预约、权限等规则继续由后端按业务验证。

## 5. AI 与验证

正式 AI 采用 NestJS + Mastra，默认同进程、同镜像；API 与后台进程仍属于同一 AI 业务域。可选原理练习 `G0` 与 Go 语言无关。

框架能力不自动提供业务授权、正确工具执行或可靠评测。Agent 的请求上下文、预算、工具权限、确认与恢复按专项设计验证。

技术覆盖通过可运行流程、关键测试、性能测量与故障演练体现。目录、依赖数量或微服务数量都不能作为完成证据；现状以 [状态表](../status.md) 为准。

## 6. 代价与再评估触发点

- 预留全部职责目录会增加文档维护；只为实际阶段添加依赖、配置和代码，避免长期伪实现。
- 多数据库、服务拆分和多协议提高运行与恢复成本；实际拆分前需验证接口、数据归属和独立部署收益。
- App 的原生体验/复用优先级、小程序功能范围、桌面离线需求明确后，另写客户端选型决定。
- 真正出现多人共同编辑同一对象的需求时，再记录内容模型、编辑器和同步存储的专项决定与迁移方案。
