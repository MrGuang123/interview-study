# 阶段 2：第一条真实业务链路

日期：2026-10-22。状态：**实施建议，尚未实现或验证**。对应 [搭建指南](bootstrap-guide.md) 的阶段 2，是 [产品蓝图](product-blueprint.md) 中 A「个人闭环」的第一部分，尚不包含完整的提交、复习和本地草稿功能。

当前预览已被用户接受为 [UI v0 样式基线](ui-and-interaction.md)，后续可优化；继续细化用户流程、首批页面和异常交互。本文的模型与 API 仍需设计和技术约束共同校验。用户采用手写学习方式：每轮给出具体文件内容、解释和验证，由用户亲手完成，不只创建目录。

## 1. 本阶段做成什么

一个真实账号登录后，打开一道题，开始一次私人练习，输入回答并手动保存。回答进入 PostgreSQL；刷新、重新登录或另一个设备登录后，仍能打开这次练习并看到回答。其他账号无法读取或修改它。

主链路：Web 页面 → HTTP API → Nest Controller → 业务 Service → core 自有 Prisma 数据访问 → PostgreSQL。读取时沿反方向返回。登录、权限、输入校验和版本规则由 core-api 执行。

只需要启动 `web`、`core-api` 和 PostgreSQL。先使用 REST 完成这条简单链路；GraphQL 留给后续工作台聚合，不为同一功能重复实现两套接口。其他服务、Redis、MongoDB、Socket、3D、Worker/Workbox 和 AI 按既有阶段继续加入。

## 2. 可演示的用户故事

1. 开发种子脚本准备两个可登录账号、三道只读题目，不依赖手工在数据库敲数据。
2. 用户 A 登录，在题目列表选择一道题并开始练习，进入带稳定练习 ID 的 URL。
3. 输入「闭包的用途是……」，点击保存，界面先显示保存中，服务端确认后显示已保存。
4. 刷新页面，回答仍在；重新登录后可从“我的练习”入口重新打开，不依赖记住 URL。
5. 另一个浏览器/设备登录 A，可看到同一份已保存内容；退出其中一个会话不影响另一个。
6. 用户 B 无法通过替换练习 ID 读取或修改 A 的回答。
7. 两个会话编辑同一旧版本时，后保存的一方收到冲突提示，自己的未保存文字仍保留。

这里的“保存”只代表云端草稿保存成功，不等于正式提交、自动评分或后台报告完成。开发账号不能变成线上共享默认账号；本地 seed 必须明确限定开发环境，密码通过本地配置传入并哈希保存。

### 2.6：接入数据层

Prisma 的依赖、生成器、配置文件和命令取决于实际选定的大版本，安装前对照该版本官方文档和当前应用模块配置核实，并锁进根依赖锁文件。当前 core-api 使用 CommonJS 输出与无扩展名导入，具体代码见 [02B](lesson-02b-prisma-connection.md)。不混抄不同版本教程，也不要求用户填写版本占位符。

只在 `apps/core-api` 内拥有其模型、生成配置和迁移，不建立供所有服务共享的 PrismaService。core-api 已改为 CommonJS，其他 Nest 应用仍有 ESM 配置；生成客户端的模块格式、导入路径、构建输出和生产启动按所属应用一起验证。[Nest Prisma 指南](https://docs.nestjs.com/recipes/prisma)

先写模型、生成并审查迁移 SQL，再执行迁移和开发 seed。已有数据上的破坏性重置不作为日常迁移方法；数据库集成测试使用独立测试库。

建议的逻辑模型如下；认证库可能提供相应表结构，选定后映射职责即可，不机械重复建表：

| 模型 | 必要职责 |
| --- | --- |
| User | 稳定用户 ID、显示名称、账号状态 |
| LoginIdentity / PasswordCredential | 登录标识与密码哈希；和用户资料分开 |
| DeviceSession | 用户关联、独立会话、到期与撤销信息；会话秘密不以明文存储 |
| Question + QuestionVersion | 稳定题目及不可变发布题干；练习引用具体题目版本 |
| PracticeAttempt | 练习 ID、ownerUserId、questionVersionId、回答草稿、revision、contentFormatVersion、时间 |
| WriteReceipt | 用户范围的操作 ID、操作类别、资源、请求摘要、已完成结果，用于写入去重 |

练习草稿可以直接存在 PracticeAttempt 上，不先拆一套通用文档/历史引擎。`revision` 检测内容并发，`contentFormatVersion` 描述内容编码，两者不同。题目首版只读；正式提交出现时再增加 Submission，不能把可编辑草稿冒充不可变提交。

私人练习先按用户归属授权；小组业务出现时再兼容增加 Workspace/Membership，不为首条链路提前实现整套组织管理。

### 2.7—2.9：在 API 层实现并验证规则

接口路径是建议，落代码前固定请求/响应和错误契约：

| 接口 | 作用 |
| --- | --- |
| POST /api/v1/auth/login | 验证凭据、创建独立会话 |
| GET /api/v1/auth/me | 恢复当前登录状态 |
| POST /api/v1/auth/logout | 撤销当前会话 |
| GET /api/v1/questions | 分页列出只读发布题目 |
| GET /api/v1/questions/:id | 读取发布题干和其版本 ID |
| POST /api/v1/practice-attempts | 根据 questionVersionId 创建私人练习，支持操作去重 |
| GET /api/v1/practice-attempts | 分页列出自己的练习，提供重新进入入口 |
| GET /api/v1/practice-attempts/:id | 读取自己的练习及云端草稿 |
| PUT /api/v1/practice-attempts/:id/draft | 带操作 ID 和基础版本保存草稿 |
| GET /health/live、GET /health/ready | 区分进程存活与数据库就绪 |

Web 首版建议使用服务端持久会话 + HttpOnly Cookie；每次登录独立会话。实现时选用经过核验的认证组件，不自行发明密码算法。密码哈希、到期/撤销、生产 HTTPS/Secure、SameSite、写请求及登录的 CSRF 防护、登录限流都纳入身份模块。Cookie 属性不能代替对象权限校验。[Nest 认证指南](https://docs.nestjs.com/security/authentication)

开发建议由 Next 将浏览器同源 `/api/v1` 转发到 core-api，业务接口路径保持一致。转发需验证 Cookie、原始 Origin/可信代理与 CSRF 配置；同源转发不代替鉴权，也不让 Next 拥有业务规则。另一设备访问需要可达的后端入口；`localhost` 只指该设备自己。上线使用真实 HTTPS 入口，不能照搬开发 Cookie 策略。

每个输入均运行时校验，包括字符串长度、ID、分页上限、版本和正文格式；服务端从会话获得用户身份，不接受请求体指定 ownerUserId/角色。Nest 提供全局校验管线和字段白名单机制；具体采用类 DTO 还是 schema 在实施时统一选择。[Nest 校验指南](https://docs.nestjs.com/techniques/validation)

错误格式至少包含稳定业务 code、可展示 message、requestId；400 为非法输入、401 为身份失效、409 为版本冲突。私人练习对无权限对象统一按约定返回 404，避免泄露对象存在性。未预期错误不向客户端返回堆栈或连接信息。

结构化日志记录 requestId、路由、状态、耗时和受控错误分类，不记录密码、Cookie、数据库地址中的凭据及完整回答正文。已有 Observe 是否接云端不影响本阶段先做好本地可排障日志。

### 保存时的并发与重试

请求示意，字段名尚待实施固定：

```json
{
  "operationId": "client-generated-unique-operation-id",
  "baseVersion": 3,
  "contentFormatVersion": 1,
  "body": "闭包的用途是……"
}
```

同一次操作重试复用 operationId，用户产生新内容并再次保存则使用新 ID。服务端处理顺序：

1. 验证会话和当前用户对该练习的访问权。
2. 查用户范围内的操作回执；相同操作、相同请求返回原结果，相同 ID 换内容则拒绝。响应曾丢失的成功保存不能因为基础版本已旧而被误报冲突。
3. 新操作开启数据库事务，先插入由用户与操作 ID 等适当范围构成唯一键的操作记录，利用唯一约束序列化同一操作的并发请求；再使用所有者、资源 ID、基础 revision 共同作为原子更新条件，成功后递增 revision，并填入成功回执。整个事务一起提交或回滚，不留下已提交的半完成操作。
4. 并发重复请求遇到唯一键冲突时，先让失败事务回滚，再在新事务/查询中核对已提交的回执和请求摘要，返回原结果。不能在 PostgreSQL 已失败的事务内继续查询，也不能让同一操作的并发重试在版本检查处被误报成新操作冲突。没有可复用成功回执时，按受控重试或明确错误处理，不无条件反复执行副作用。
5. 旧版本新操作返回 409；前端保留编辑文本，提供比较/重新加载后的人工合并，不自动覆盖远端。

事务负责相关写入的一起成功或回滚，版本条件和唯一约束分别负责冲突检测、去重；这些是本项目业务设计，不能只靠禁用保存按钮实现。[Prisma 事务说明](https://www.prisma.io/docs/orm/fundamentals/transactions)

### 2.10：实现已设计的页面并接入

依据前面已经选定的主题、页面规范和交互原型实现四个入口：`/login`、`/questions`、`/app/practice`（我的练习）、`/app/practice/[attemptId]`。路由可随信息架构调整。答题页展示题目、输入框、保存状态和最近成功保存时间；第一版纯文本即可，不提前引入富文本和协同编辑器。

- App Router 页面负责路由/布局/初始读取边界；输入和保存交互放小范围客户端组件，不把整站机械改为客户端组件。
- Axios 负责浏览器请求适配与错误转换，TanStack Query 管理身份/题目/练习等远程结果与保存后的缓存更新。
- 正在编辑的文本使用局部 React 状态，与最后成功保存的服务器快照区分；后台 refetch 不直接覆盖未保存输入。
- 保存中仍允许编辑时，响应只确认当次请求对应的快照；用户后来输入的内容继续显示未保存。首版也可明确锁定保存期间输入来简化，但不能错误标记新文字已保存。
- Query key、缓存清理和登录退出按账号隔离；退出/切号处理未保存输入，不能显示上个账号的私有数据。
- Tailwind/shadcn 负责页面与组件。尚未形成真实跨页界面状态时，不为使用 Zustand 而复制 Query 数据。

空题库、加载失败、登录过期、保存失败、版本冲突都要有明确界面。服务端确认前不能显示“已保存”；前端路由隐藏也不能代替 API 权限。

## 5. 阶段验收

| 场景 | 必须看到的结果 |
| --- | --- |
| 保存后刷新/重新登录 | 从 PostgreSQL 重新读取已保存答案 |
| 同账号第二个独立会话 | 能从我的练习打开并读取内容；不需要实时 Socket 才能成立 |
| A、B 两个不同账号 | B 列表不出现 A 的练习，猜到 ID 也不能读取或写入 |
| 未登录、退出或过期 | 受保护操作返回 401；退出 A 的一个会话不撤销其他会话 |
| 版本并发 | 两个会话读取 v1；一方保存成 v2，另一方的旧版本保存被拒绝且编辑文本保留 |
| 重复操作/响应丢失 | 同一操作最多产生一次业务写入；相同操作 ID 改内容被拒绝；并发重复请求也遵守规则 |
| 中途数据库错误 | 回答与回执一起回滚，不出现半份成功 |
| 数据库停机/恢复 | ready 失败，保存不假成功；恢复后可明确重试 |
| 重启依赖/应用 | 已保存数据保留；不将其描述为已完成备份恢复 |
| 输入和页面 | 超长/非法输入被拒绝；主要操作可键盘完成；加载/空数据/错误可辨认 |

测试对应真实风险：Service 单测覆盖规则，使用 PostgreSQL 的集成/API 测试覆盖权限、约束、事务和会话；Playwright 覆盖至少一条登录、保存、刷新恢复的浏览器流程。仅 mock Prisma 无法证明迁移、唯一约束和事务正确。

交付运行手册记录从干净检出到安装、迁移、开发 seed、启动、检查和生产构建的实际命令。部署配置仅覆盖当前 Web/core/PG，明确 HTTPS 和凭据设置，不同时铺开所有服务；执行部署后另记环境和结果。自动发布、全服务观测、应用回退、隔离数据库恢复仍按后续阶段完成。

## 6. 每步应能解释的知识

| 步骤 | 学完后能解释什么 |
| --- | --- |
| 产品与 UI | 用户流程如何转化为页面、主题、组件状态与数据契约；设计令牌如何保持一致 |
| 数据库 | 表、外键、唯一约束、索引、迁移、持久化卷和备份的区别 |
| Nest/Prisma | 模块装配、依赖注入、配置、模块格式与构建、连接和事务边界 |
| 身份与权限 | 登录身份、用户、设备会话和对象所有权分别解决什么问题 |
| 保存可靠性 | 幂等与版本冲突有什么区别，为什么需要数据库原子条件与唯一约束 |
| React/Next | 服务端与客户端边界、表单状态、请求状态、缓存与编辑快照如何协作 |
| 测试与排障 | 如何证明答案真的持久化、没有越权，以及失败发生在哪一层 |
