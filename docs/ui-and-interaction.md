# 全站 UI 与首条业务链路的交互设计

日期：2026-10-22。状态：**用户已接受浅深色渐变方向，并要求扩展全站图稿与设计令牌**。[UI-design](../UI-design/README.md) 已按 17 类页面建立浅/深色设计板，每板含桌面与 H5，另有关键异常状态板；[完整令牌源](../packages/design-tokens/src/tokens.json) 已建立。静态图稿不等于逐页用户验收、完整可点击原型或业务实现，尚未接入真实业务 API。

对应 [阶段 2 实施清单](stage-2-first-slice.md)。目标流程是登录 → 选题 → 开始练习 → 编辑 → 保存 → 从我的练习继续；数据库、权限和可靠保存仍须按该清单实现。

## 1. 设计顺序和范围

1. 用户流程与信息架构：确定入口、导航、页面关系、关键动作和内容优先级。
2. 低保真线框：先确定内容和布局，重点检查题目、编辑区、保存状态与恢复入口是否容易理解。
3. 视觉方向比较：用相同内容、同一个代表页面比较候选，选择后记录首批视觉规范。
4. 关键页面与状态：把规范应用到首条链路，制作可点击原型或明确标注模拟数据的静态交互预览。
5. 根据原型细化数据/API 契约，同时检查服务端规则、延迟和错误是否能在界面表达，再分步开发联调。

全站设计范围现已扩展为 17 类页面，清单与路由见 [图稿索引](../UI-design/manifest.json)，覆盖登录、工作台、题库与详情、练习与复盘、房间、实验室、小组、档案、离线、AI、管理、账号和题目编辑。实现仍从登录、题库、我的练习、答题四个入口开始；后续页面的图稿只表达目标交互，不代表功能已可用。

独立的 PostgreSQL 启动、连接和数据卷验证可以并行。视觉配色不决定表结构，但页面中的状态、操作及恢复路径会影响数据和接口；设计与技术应相互校验，不能分别定死后再勉强拼接。

## 2. 首条链路四个页面要解决的问题

| 页面 | 内容与主要操作 | 设计要回答的问题 |
| --- | --- | --- |
| 登录 | 登录标识、密码、错误提示、登录操作和成功跳转 | 错误出现在哪里？登录过期后是否能返回原练习？ |
| 题库 | 题目名称、分类/摘要、分页、开始练习 | 能否快速理解题目？开始练习与继续已有练习如何区分？ |
| 我的练习 | 题目、最近保存时间、状态、继续入口 | 重新登录后如何找到回答？列表为空时下一步做什么？ |
| 答题 | 完整题干、编辑区、保存按钮、保存状态和返回入口 | 阅读与输入如何布局？未保存文本、保存快照和冲突怎样表达？ |

至少提供桌面布局与 H5 窄屏布局。先用代表性宽窄画布检查内容，再根据布局选择断点；不能将桌面两列等比例缩小当作移动适配。App、小程序、桌面壳的具体实现仍待后续选型。

## 3. 主题不是只选一个主色

用户已明确同时需要**专业工具感与技术实验感**，并接受浅深色渐变预览。渐变用于标题周边柔光、主按钮和选中区域；阅读、输入和聊天表面保持纯色。共用视觉规则已写入令牌，后续以使用反馈优化，不再将重复选主题作为开发前置；完整交互与浏览器行为继续按阶段验证。

字体优先系统无衬线与中文回退，代码用系统等宽字体；初版正文基准 14px，区块标题约 18—23px，页面标题依层级放大。面板圆角 14px、窗口 18px、按钮 8px，桌面主间距 22px；微交互约 150—180ms，专注面板过渡约 260ms，并支持减少动效偏好。正式数值、渐变、阴影、控件高度与响应式规则以 [tokens.json](../packages/design-tokens/src/tokens.json) 为准，图片不作为逐像素规范；Web 映射与组件实现尚未建立。

桌面实验布局为窄导航、上方题目/概念路径、下方回答区与侧边提纲；H5 使用水平导航与纵向内容。概念图和提纲目前是静态演示，不声称已有 AI 或真实计算功能。初版浅深外观跟随系统，不因此把主题切换设置标成已实现。

候选以清晰、克制的专业操作骨架承载长期阅读和答题：导航、内容层级、编辑工具与保存状态保持易懂。技术实验感通过适合的局部表达探索，例如结构化的题目上下文、面板切换、状态反馈或未来实验区域；设计巧思需要帮助用户理解和操作，避免装饰占据主要任务。

需要比较和记录的项目：

- 内容气质与信息密度：在专业工具与技术实验的共同方向下，比较阅读舒适度、操作密度和局部表达强度。
- 页面结构：导航位置、内容宽度、题目与编辑区的关系、列表/卡片取舍和窄屏折叠方式。
- 色彩：背景、表面、文字层级、边框、强调色、成功/警告/危险/焦点语义。
- 字体与排版：中文正文、代码、标题层级、行高和长题干的阅读宽度。
- 间距、圆角、阴影、图标、控件尺寸和必要动效。
- 明暗模式首版跟随系统，浅深色页面图稿已建立；实际对比度、焦点和交互仍需在浏览器逐步验证，手动切换设置尚未实现。
- 组件规则：按钮层级、输入框、列表/卡片、提示、对话框、加载和空状态。

已知技术方向为 Tailwind + shadcn。组件库提供基础构件，产品的布局、主题和交互规则仍需要设计；不能直接把生成器默认外观当作用户已选择的主题。

原对比稿使用同一答题工作区、相同内容和状态，比较共同方向的不同实现。当前渐变方向已扩展到全站图稿与平台中立令牌；布局和细节仍可依据实际使用优化。页面清单与 Tailwind 基础映射的手写步骤见 [页面与主题使用指南](ui-theme-guide.md)，包清单、生成器、CSS 输出和应用集成尚未落代码。

### 动效规则

- 动效表达切换的空间关系、面板展开与收起、焦点和上下文变化，以及保存中、成功、失败等反馈；重要结果同时有文字或图标，不依赖动画传达。
- 编辑输入、阅读和保存等主要操作保持响应及时；过渡不遮挡内容、不改变输入焦点，也不要求等待动画结束才能继续。
- 支持系统的减少动效偏好，减少位移、缩放与持续运动，必要时直接切换状态；内容和操作能力保持完整。
- 候选预览可展示少量代表过渡，主题确认后再记录持续时间、缓动、适用场景和减少动效行为。装饰动画或持续运行的 3D 不作为默认要求。

## 4. 关键交互状态

| 场景 | 设计交付需表达的行为 |
| --- | --- |
| 读取中/加载失败 | 内容占位、错误位置和重试入口 |
| 空题库/无练习 | 说明当前为空，并提供实际可用的下一步 |
| 登录失败/会话过期 | 明确提示；重新登录前如何保留正在编辑的内容需说明 |
| 尚未修改/未保存/保存中/已保存 | 状态文案和按钮行为一致；已保存只对应服务端确认的文本快照 |
| 保存失败 | 保留输入，说明失败并提供重试；模拟预览必须标明未真实落库 |
| 保存中继续输入 | 请求返回后，后输入的文本仍显示未保存，不能被旧响应覆盖 |
| 旧版本冲突 | 显示冲突、远端版本与本地内容，提供比较/重新加载后的处理；不静默覆盖 |
| 离开/退出/切号 | 对未保存内容给出清晰去向；账号之间不展示或重放对方内容 |

会话过期后的编辑保留、返回页面和重新鉴权应先在原型里说明，再由实现验证。首轮内存中的输入保护不代表刷新后或断网时已有本地草稿恢复。

## 5. 设计交付物与检查方式

| 交付物 | 检查方式 |
| --- | --- |
| 首条用户流程和整站导航骨架 | 用户能从进入、保存到重新打开自己的练习，入口连贯 |
| 17 类页面的浅深色桌面/H5 静态图稿 | 已保存；内容、动作、页面关系可评审，仍需真实窄屏与长内容验证 |
| 同一代表页的主题候选稿与选择记录 | 可以比较风格差异；记录用户采用的方向和仍待定的部分 |
| 平台中立令牌与组件规范 | JSON 已建立；CSS/Tailwind 映射和真实组件消费待实现 |
| 关键状态板与交互原型 | 静态状态板已建立；完整可点击链路、键盘和浏览器可访问性验收待完成 |
| 设计到契约的对应表 | 每个动作、数据字段、保存状态和业务错误有后端行为对应 |

原型评审围绕具体结果：能否找到开始/继续入口、读清题目、知道内容是否保存、理解失败后怎么办；同时检查键盘焦点、标签、对比、长内容、窄屏与触摸操作。

中立源已建立在 `packages/design-tokens/src/tokens.json`，覆盖浅深色、渐变、排版、尺寸、圆角、阴影、层级、动效与组件状态。共享包导出、CSS 生成、Web 和其他平台映射仍依实际消费者分步实施，不在页面开发后另建冲突规范。
