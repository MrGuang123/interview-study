## 2. 共用样式

- 桌面参考“实验式工作区”：窄导航、题目/概念上下文、回答区和侧提纲；题干/编辑并排的“专业工作台”也可按场景使用。
- H5 使用水平导航与纵向内容，按内容选择断点，不把桌面多列等比例缩小。
- 浅深色跟随系统；手动主题切换尚未实现。
- 正文约 14px，标题约 18—23px；系统无衬线加中文回退，代码用系统等宽字体。
- 面板圆角 14px、窗口 18px、按钮 8px，桌面主间距 22px；微交互 150—180ms，面板过渡约 260ms。
- 动效服务于切换、保存反馈和面板关系，支持减少动效。概念图/提纲目前是静态演示。
- 渐变用于标题周边柔光、主按钮和选中区域；阅读与输入保持纯色。危险色、专用焦点、控件高度、边框与状态规则已写入完整 JSON，仍需实际页面验收。

## 3. 主题分三层

~~~text
packages/design-tokens/src/tokens.json      已有：平台中立完整令牌
                 ↓ 待实现 Web 生成脚本
packages/design-tokens/web.css              待生成：CSS 变量
                 ↓ 待接入 globals.css 的 @theme inline
bg-primary / text-primary / rounded-panel   接入后页面与组件使用的工具类
~~~

设计令牌是“有名字的设计值”。primary 表示主要操作色，将来换强调色，页面仍用 `bg-primary`。

实际安装 Tailwind **4.3.3**，使用 CSS 中的 `@theme`；本任务沿用现有 Next/Turbopack 配置，无须额外新增旧教程的 `tailwind.config.js` 或 PostCSS 配置。引用其他 CSS 变量时使用 `@theme inline`，参见 [官方主题文档](https://tailwindcss.com/docs/theme#referencing-other-variables)。

下面示范“主题包 → Web → 一个样例页”的基础映射。`tokens.json` 已存在，直接使用，不要重建或覆盖；其余文件仍待按手写学习方式创建/修改。此示例只映射颜色、字号、圆角、间距和时长，尚未映射渐变、阴影、布局、组件绑定、别名解析等完整令牌，不能据此认定全站主题已经集成。

### 3.2 使用现存 packages/design-tokens/src/tokens.json

[tokens.json](../packages/design-tokens/src/tokens.json) 是当前唯一权威令牌源，已包含颜色、渐变、字体、行高、尺寸、圆角、阴影、层级、动效、断点、布局和组件状态。不要用旧教程的精简 JSON 覆盖它。字段含义、单位与引用规则见文件内 `meta`；平台映射说明见 [令牌包 README](../packages/design-tokens/README.md)。

尺寸使用平台中立设计数值，Web 可按每 rem 对应 16px 转换适合缩放的值；断点、视口比例、无单位行高等应按各自单位处理，其他平台自行映射。下方入门脚本仅消费兼容的平面字段，不会生成完整渐变或组件规则。

### 3.3 新建 packages/design-tokens/scripts/build-web.mjs

~~~js
import { readFile, writeFile } from "node:fs/promises";

const source = new URL("../src/tokens.json", import.meta.url);
const target = new URL("../web.css", import.meta.url);
const tokens = JSON.parse(await readFile(source, "utf8"));

const declarations = (prefix, values, format = String) =>
  Object.entries(values)
    .map(([name, value]) => "  --forge-" + prefix + "-" + name + ": " + format(value) + ";")
    .join("\n");

const rem = (value) => String(value / 16) + "rem";
const lightNames = Object.keys(tokens.colors.light).sort().join(",");
const darkNames = Object.keys(tokens.colors.dark).sort().join(",");
if (lightNames !== darkNames) {
  throw new Error("Light and dark color tokens must have identical names.");
}

const common = [
  declarations("font-size", tokens.fontSize, rem),
  declarations("radius", tokens.radius, rem),
  declarations("spacing", tokens.spacing, rem),
  declarations("duration", tokens.duration, (value) => String(value) + "ms"),
].join("\n");

const css = [
  "/* Generated by scripts/build-web.mjs from src/tokens.json. Do not edit directly. */",
  ":root {",
  common,
  declarations("color", tokens.colors.light),
  "}",
  "@media (prefers-color-scheme: dark) {",
  "  :root {",
  declarations("color", tokens.colors.dark),
  "  }",
  "}",
  "",
].join("\n");

await writeFile(target, css, "utf8");
console.log("Generated packages/design-tokens/web.css");
~~~

例如 primary 变为 `--forge-color-primary`，radius.panel 变为 `--forge-radius-panel: 0.875rem`。脚本检查浅深色名称一致；新增名称后还需在下一步显式映射。它仅是基础教学生成器，不处理 JSON 的 gradient、shadow、layout、components 或 `$ref`；完整接入时需先补齐映射与验证，不能把嵌套对象直接输出为 CSS。

@import "@interview-forge/design-tokens/web.css";

@theme inline {
  --color-background: var(--forge-color-background);
  --color-surface: var(--forge-color-surface);
  --color-surface-muted: var(--forge-color-surface-muted);
  --color-foreground: var(--forge-color-foreground);
  --color-muted-foreground: var(--forge-color-muted-foreground);
  --color-border: var(--forge-color-border);
  --color-border-control: var(--forge-color-border-control);
  --color-primary: var(--forge-color-primary);
  --color-primary-foreground: var(--forge-color-primary-foreground);
  --color-selection: var(--forge-color-selection);
  --color-selection-foreground: var(--forge-color-selection-foreground);
  --color-focus: var(--forge-color-focus);
  --color-success: var(--forge-color-success);
  --color-warning: var(--forge-color-warning);

  --font-sans: system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif;
  --font-mono: ui-monospace, SFMono-Regular, Menlo, Consolas, monospace;
  --text-body: var(--forge-font-size-body);
  --text-heading: var(--forge-font-size-heading);
  --radius-panel: var(--forge-radius-panel);
  --radius-window: var(--forge-radius-window);
  --radius-control: var(--forge-radius-control);
  --spacing-workspace: var(--forge-spacing-workspace);
}

@layer base {
  :root {
    color-scheme: light;
  }

  @media (prefers-color-scheme: dark) {
    :root {
      color-scheme: dark;
    }
  }

  body {
    @apply bg-background text-foreground font-sans text-body;
    line-height: 1.6;
  }
}
~~~

- 普通 CSS 变量承载运行时配色；`@theme inline` 将它连接到 Tailwind。只写 `--forge-color-primary` 不会自动得到 `bg-primary`。
- `--color-primary` 对应 `bg-primary`、`text-primary` 等；`--radius-panel` 对应 `rounded-panel`；`--spacing-workspace` 对应 `p-workspace`、`gap-workspace`。
- `@layer base` 提供默认样式，页面工具类可以覆盖。浅深色使用同一组类，由媒体查询换值。

现有 `layout.tsx` 已导入 `./globals.css`，无需重复导入。body 改用系统字体，layout 中原有 Geist 加载仍保留，后续页面任务再决定是否清理。

默认首页的 `bg-white`、`bg-zinc-50`、`dark:bg-black` 会覆盖元素自己的颜色，验收应访问下一步的新样例页。

## 4. 执行命令与验收

从仓库根执行，前提是已手写上述文件。当前根没有 dev 或 test 转发脚本。

~~~sh
pnpm install
pnpm --filter @interview-forge/design-tokens run build
pnpm --filter @interview-forge/web run lint
pnpm --filter @interview-forge/web exec next typegen
pnpm --filter @interview-forge/web exec tsc --noEmit --incremental false
pnpm --filter @interview-forge/web run build
pnpm --filter @interview-forge/web run dev
~~~

`pnpm install` 建立包链接，只维护根锁文件。令牌 build 生成 `packages/design-tokens/web.css`；本任务建议将源、脚本与生成 CSS 一起提交，生成文件有来源注释。lint、typegen、tsc、生产构建验证语法、类型和实际 CSS 导入；Web 目前没有测试脚本。

开发服务器启动后，访问 [主题样例页](http://localhost:3000/theme-preview)，端口若被占用以启动输出为准。

验收结果：

1. 浅色背景 `#f6f7fb`、白色面板、强调色 `#5263dc`。
2. 系统或开发者工具模拟深色时，背景 `#10131d`、面板 `#191e2b`、强调色 `#9eaafa`；这不表示有手动主题设置。
3. 约 390px 窄屏上下排列，无横向滚动；足够宽时两列。
4. Tab 到链接和回答框有可见焦点，禁用按钮不能触发。
5. 减少动效偏好开启后，按钮过渡取消。
6. 修改 JSON 浅色 primary 并重新生成，按钮颜色改变；恢复基线后提交。不要手改生成 CSS。

改令牌后显式运行令牌 build，开发服务器通常会更新，未更新则重启 dev；本任务未增加 watch 或构建编排。新电脑安装后也先生成令牌，再构建 Web。

2026-10-22 前次将旧版六份基础示例提取到临时目录，使用本机现有 Tailwind 4.3.3 验证了基础令牌生成、CSS 导入、语义类编译、深色与减少动效规则及样例 TSX 语法。本次已扩充权威 JSON 并修正文档中的控件/选中文字映射；前次示例检查不能代表完整新令牌已集成。没有安装依赖或改动应用源码，也没有执行集成后的 Next 构建、完整类型检查或浏览器验收。手写后仍需按上述命令验收，并单独补齐渐变、阴影、布局等映射。

## 5. 开发页面怎么用

| 目的 | 使用工具类 |
| --- | --- |
| 底色和正文 | `bg-background text-foreground` |
| 卡片/面板 | `bg-surface border border-border rounded-panel` |
| 次级说明 | `text-muted-foreground` |
| 主操作 | `bg-primary text-primary-foreground rounded-control` |
| 选中项 | `bg-selection text-selection-foreground` |
| 输入框等必要边界 | `border border-border-control`，装饰分隔仍用 `border-border` |
| 键盘焦点 | `focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-focus` |
| 主间距 | `gap-workspace p-workspace` |
| 标题、正文 | 分别用 `text-heading`、`text-body` |
| 快速过渡 | `transition-colors duration-(--forge-duration-quick) motion-reduce:transition-none` |

~~~tsx
<section className="rounded-panel border border-border bg-surface p-5">
  <h2 className="text-heading font-semibold">我的练习</h2>
  <p className="mt-2 text-muted-foreground">从最近一次保存继续。</p>
</section>
~~~

页面不重复写 `bg-[#5263dc]` 之类颜色值；换色只改源令牌。布局仍由页面用 grid、flex、断点等决定，主题不会自动生成正确布局。

浅深色只涉及令牌换值时，`bg-surface` 自己会变，不必重复写 dark 配色；确有布局/资源差异才加相应规则。

状态类保持完整字符串，例如：

~~~tsx
const statusStyles = {
  saved: "text-success",
  pending: "text-muted-foreground",
  retrying: "text-warning",
};
~~~

这里只示范样式映射；真实保存状态由请求与服务端确认决定。不要用 `"text-" + color` 动态拼类名，Tailwind 不解析 JavaScript 来推断完整类名，参见 [官方类名检测文档](https://tailwindcss.com/docs/detecting-classes-in-source-files#dynamic-class-names)。
